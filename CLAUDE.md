# FENRIR — notes for coding agents

Open-source BLE climbing dynamometer. Separate from LeBlond; LeBlond integrates it through
`software/leblond-integration`. The brief is summarised in `docs/requirements/requirements.md`.

## Non-negotiables

- **Never claim a physical result that was not physically obtained.** Every statement is one of:
  target, estimate, simulated, software-tested, electrically measured, physically validated
  (definitions in `docs/requirements/requirements.md`). Update `docs/verification/verification-matrix.md`
  with the real status; never mark an unperformed test as passed.
- **FENRIR is not safety equipment.** Do not write anything that authorises hanging a person from it,
  dynamic loading, or use at full range without a proof-load record.
- Plastic, PCB and battery are never in the load path.
- Raw ADC counts are never modified. Filtering applies only to derived force and is flagged.
  A clipped or missing sample is reported as invalid, never as a number.
- A 24-bit ADC is not 24-bit accuracy; a 2000 N cell rating is not a 2000 N safe working range.
- Do not buy anything, submit manufacturing orders, or modify LeBlond's repository, database or
  deployment. LeBlond lives in `../repo` — read-only from here.
- Prices and stock in the BOM carry a source and a date. Do not add a price without both; write
  `NOT VERIFIED` instead.
- Component facts come from datasheets. If you could not read it, say so.

## Architecture

```
load cell → NAU7802 (I²C) → ESP32 (firmware) → BLE GATT v1 → client (Python / TypeScript) → LeBlond
```

- `firmware/src/core` + `firmware/include/fenrir`: portable C11, no hardware access, host-tested.
  All measurement decisions live here (protocol encoding, calibration, filter, guard, tare, config CRC,
  NAU7802 driver over a bus HAL).
- `firmware/src/platform/esp32/main.cpp`: Arduino core 3.x + NimBLE-Arduino 2.x glue only.
- `protocol/fenrir-gatt-v1.md` is the contract. `protocol/vectors/v1.txt` is generated by the firmware
  encoder and tested by Python and TypeScript. A protocol change means: edit the spec, the three
  codecs, regenerate vectors (`make -C firmware/tests vectors`), bump the version.
- `software/fenrir`: `protocol.py`, `model.py` (recording, loss accounting), `metrics.py` (pure
  functions), `simulator/`, `calibration/`, `diagnostics/`.
- `software/leblond-integration/src`: dependency-free TypeScript (`protocol.ts`, `recording.ts`,
  `device.ts`). Erasable syntax only (no `enum`, no parameter properties): tests run with Node's type
  stripping.

## Verification commands (run all before finishing)

```bash
.venv/Scripts/python -m pytest
```

```bash
docker run --rm -v "$PWD:/w" -w /w/firmware/tests gcc:13 make test
```

```bash
npm test --prefix software/leblond-integration
```

```bash
pio run -d firmware -e feather_esp32c6
```

In Git Bash on Windows prefix the Docker command with `MSYS_NO_PATHCONV=1` and use the absolute
Windows path instead of `$PWD`. Run `pio` from PowerShell, not Git Bash (the ESP-IDF tool installer
rejects MSYS), and set `PLATFORMIO_CORE_DIR` to a drive with ~8 GB free.

## Conventions

- C: C11, `fenrir_` prefix, fixed-width types, no dynamic allocation, builds clean with
  `-Wall -Wextra -Wpedantic -Wconversion -Wshadow -Werror`.
- Python ≥ 3.11, numpy only at runtime (`bleak`, `matplotlib` optional). Metrics are pure functions
  with documented windows and thresholds.
- Units: newtons everywhere internally; centinewtons on the wire; kgf and lbf only for display.
- Requirement IDs (F-, M-, S-, C-), decision IDs (D-), risk IDs (R-), test IDs (V-) are stable: add,
  never renumber.
- New engineering choices get a row in `docs/decisions/decision-log.md`.
- Simulator output must always be labelled as simulated.
